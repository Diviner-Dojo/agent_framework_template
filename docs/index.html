01 — The problem

AI can write the code. It can't be trusted to grade its own homework.

Agentic coding tools got very good very fast. The bottleneck moved. It is no longer can the model write this — it's can you trust what came out, and can you explain it later. Four failure modes show up in every unstructured AI codebase.

The reasoning evaporates

An agent makes hundreds of judgement calls — boundaries, trade-offs, what to skip. The code survives. The why does not. Six months later nobody, human or model, can reconstruct the argument.

The author is the reviewer

The same context that produced the bug evaluates the bug. Confirmation loops close in one turn. An agent that misunderstood the requirement will confidently confirm it met the requirement.

Quality is a coin flip

Same model, same codebase, wildly different output depending on how the session went. Nothing is enforced, so nothing is consistent. Standards live in your head and erode under deadline.

Every session starts from zero

A dead end you burned two hours on last week gets rediscovered next Tuesday. Nothing accumulates. The project has no memory, so the same mistakes stay available forever.

02 — The thesis

Treat the reasoning as the deliverable and the code as its exhaust.

Reasoning is the primary artifact. Code is output. Principle #1 — the load-bearing one

Every mechanism in this framework follows from that inversion. If the reasoning is what matters, then it has to be captured automatically (you can't opt out of logging), evaluated independently (the author never grades itself), and promoted deliberately (a human decides what becomes durable memory).

Capture is not optional

Enforced at the command and hook layer, not by asking the model nicely. /review, /plan, and /build_module each open a discussion and write every agent turn to an append-only log.

Independence is structural

At least one specialist who did not participate in generation must review the result. It's not a suggestion in a prompt — it's the shape of the workflow.

The human holds the gates

Nothing is promoted to durable memory, merged, or pushed without a person. Autonomy removes the permission prompts, never the checkpoints.

Prime Objective — refuse extraction ADR-0015

Above the nine principles sits a declared ethic: the framework must serve its contributors and users and never accumulate value at their expense. A design refuses extraction only if every contributor keeps attribution, nobody performs labour whose benefit accrues to a third party without consent, and evolution never harvests value from derivatives without per-instance human assent. Enforcement is human-mediated at every gate — the framework supplies the gate; a person renders the verdict.

04 — Mechanics

What actually happens when you change a file.

The framework doesn't change how you write code. It changes what has to be true before that code is allowed to land.

Write→ /review→ Fix blocking findings→ Quality gate→ Commit→ Captured
01

Risk is assessed before the panel is picked

The facilitator — the only agent that orchestrates others — sizes the change against a risk matrix and assembles the specialists that matter. A theme tweak gets two reviewers in ensemble mode. An auth change gets an adversarial panel of five or six.

02

Specialists run in parallel, in isolation

Each gets its own context window and its own domain lens. They do not see each other's drafts in ensemble mode — that's the point. Findings are graded blocking or advisory, and the facilitator re-reads the code at each reported location before it believes a claim.

03

The gate runs whether you remember it or not

A pre-commit hook runs quality_gate.py: formatting, lint, tests, coverage, ADR completeness, review existence, and the regression ledger. Fail any of them and git refuses the commit. Every run is appended to a JSONL log you can trend later.

04

The argument outlives the session

The whole review — every turn, every dissent, every verdict — is sealed into an immutable discussion, indexed into SQLite, and mined for recurring patterns. Next month's agent can grep what this month's agent already learned.

05 — The team

Twelve agents. One orchestrator. No agent reviews its own work.

Each specialist carries a values block (what it believes and won't trade away) and a domain lens (the reasoning sequence it runs before analysing anything). They are equal in standing and different in strength.

Five collaboration modes

Ensemble — independent, no exchange. Yes-And — each builds on the last. Structured dialogue — multi-round coopetition, the default for significant changes. Dialectic synthesis — thesis/antithesis with an ACH matrix. Adversarial — red team, deliberately scoped to security, fault injection, and anti-groupthink only.

Specialists can ask for help

Any specialist can file a dispatch_request for another agent's expertise, or a split_request to run as parallel instances. Requests go through the facilitator, and both the request and the decision are captured — so you can later ask which collaborations actually produced value.

07 — Enforcement

The parts that say no.

A framework nobody follows under pressure is decoration. These run at the tooling layer, where forgetting isn't an option.

Nine hooks across six lifecycle events

Before a write: atomic file locks so parallel agents can't clobber each other, a 12-pattern secret scanner, and a protected-file deny-list (.env, .git/, the metrics DB, settings.json).
Before a commit: the quality gate. Before a push: a main-branch blocker.
Around the session: auto-format, lock release, context-occupancy monitoring, compaction checkpointing, and a session-start state restore.

Eight checks in the quality gate

Formatting · lint · tests · coverage floor · ADR completeness · review existence (code staged with no review from today = blocked) · regression ledger (known bugs must still have guard tests) · session-state freshness. --fix auto-remediates; every run is logged.

"Proceed without asking" ≠ "proceed without reviewing"

The framework supports genuinely autonomous execution — a scoped authorization block lets an agent run the full workflow overnight without a permission prompt at every step. It explicitly does not authorise skipping steps. Never /plan. Never /review. Never capture. Never a push. That distinction is written into a rule loaded on every turn, because a derived project once shipped seven workstreams without a single independent evaluation and it took a rule to stop it happening twice.

08 — Compounding

Three nested loops, and one that closes.

Micro — per change

Review findings become fixes. Fixes become regression tests. The test becomes a ledger entry naming the root-cause class, so the next similar bug is recognised, not rediscovered.

Meso — per sprint

/retro reads every discussion from the sprint, clusters what went wrong, and proposes process adjustments. Recurring findings get surfaced by the Rule of Three: seen in three independent contexts, it graduates.

Macro — per quarter

/meta-review evaluates the framework itself — agent effectiveness, architectural drift, whether a rule is earning its context budget. Changes route through the steward and then a human.

The loop that closes on itself

The framework grades its own findings — severity, category, noise. For a long time it never read those grades back. scripts/audit_calibration.py now does: it reads the metrics DB, measures per-agent calibration error and heuristic-vs-recorded severity disagreement, and writes proposals. It is deliberately forbidden from acting on them. Tightening a classifier is a human edit, because an agent that edits its own grading rubric is not improving — it's drifting.

ADR-0024 · advisory only, never gate-blocking

09 — Ownership

You do not merge code you cannot explain.

The failure mode nobody talks about: an AI-built codebase whose owner can't debug it at 2am. The education gate exists to keep the human genuinely in the loop rather than nominally on the approval line.

Walkthrough

The educator agent traces the change and the reasoning behind it, at the depth the change warrants.

Quiz

Bloom's-mixed questions, 70% to pass. At least one debug scenario and one change-impact question.

Explain back

You articulate the design in your own words. This is the step that catches shallow understanding.

Merge

Deferrals are allowed — but logged, and owed before the next phase starts.

Educational intensity adapts: as you demonstrate competence in an area, the scaffolding fades.

10 — Honest status

What's load-bearing, and what's still moving.

This has been running daily since March 2026 across three codebases. Some of it is boring and dependable. Some of it is a live experiment. Here is which is which.

Proven in daily use

The review panel and risk tiers · the quality gate and pre-commit enforcement · the four-layer capture stack · ADR discipline · the regression ledger and its guard tests · the hook set · autonomous execution with human gates · /plan → /build_module → /review sequencing.

Proof-of-concept — expect movement

The sourced-assertion memory substrate (ADR-0014) · framework lineage and drift tracking · goal-driven loop orchestration (ADR-0026/0028) · telemetry and oversight dashboards (ADR-0020) · the confidence-calibration back-flow (ADR-0024) · the progressive-disclosure restructure of the constitution itself.

Known limitations, stated up front

The pre-commit hook can't pass --skip-reviews through, so the review-existence check can't be bypassed from git commit. The gate's 5-minute verification cache can silently suppress the regression-ledger reminder. Review-existence verifies that a review from today exists — not that it covered the exact files you staged. These are documented in CLAUDE.md rather than discovered by you. Pin a version if you need stability — the framework changes weekly.

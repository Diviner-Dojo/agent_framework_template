# REV-20260807-164855 — Wave 1/1b/1c blind review

**Verdict: 4 of 6 slices passed independent review. 0 blocking findings outstanding on passed
slices.** S9 and S10 did not pass and continued into Wave 1d.

## Method

Each slice was written by one agent and reviewed by a different agent that **did not see the
writer's reasoning** — only `git diff` over the slice's declared file scope, plus a statement of
stakes. Critics were instructed to assume the work was wrong and to re-run every claim themselves.
A slice passed only when its critic could answer an emphatic YES to five questions, one of which
(*did measurement get thinner?*) was a **veto**: NO forced a send-back regardless of everything else.

This is merged Principle #3 — the generator is never the sole evaluator — implemented as an
information property rather than a personality.

## What the critics caught that the builders did not

These are recorded because they are the argument for the review layer, not decoration.

1. **S2 — the veto fired.** The repaired `retro.md` dropped `agent_count` on the pre-migration
   schema, which is **agentic_journal's live schema**. A change whose purpose was to repair an
   instrument would have silently thinned that instrument in the derived project that uses `/retro`
   most (214 derived references vs 55 template-local). Fixed and re-proved against scratch copies of
   all four real databases.

2. **S1 — a governance guarantee with nothing behind it.** Three live files, including `CLAUDE.md`
   and `PHILOSOPHY.md`, asserted that review plurality was "specified in `/review`". The critic
   grepped `review.md` and found that measurably false. Resolved by placing a byte-identical panel-size
   rule in both `selecting-review-gates` and `review.md`, plus a general test that fails when a
   governance claim names a file not containing the mechanism it claims. 18 of 18 mutations killed.

3. **S0 — a reconstruction presented as a source.** An earlier round re-pointed
   `REV-20260807-063650.md`'s `discussion_id` at a discussion hand-written ~11 hours later from the
   review's own text, and disclosed it nowhere. Resolved with a machine-readable
   `discussion_provenance: transcribed-post-hoc` marker plus prose in the file a reader actually
   opens. The critic then rebuilt the resulting integrity check **from its prose alone** and landed
   on identical counts (107 checked / 95 intact / 12 severed), which is the strongest evidence in
   this review that the spec is real.

4. **S0 — an unmeasured count inside a document about unmeasured counts.** ADR-0032 asserted "three
   sealed zero-event discussions". Measured: **four** zero-byte `events.jsonl`, only **one** actually
   sealed. The builder had verified every fenced code block and skipped the prose.

5. **S9 — the architecture was wrong, not the enumeration.** Three successive rounds found new
   bypasses of a command-text guard (shell grouping, `&&` chaining, `bash -lc`, mis-parsed
   `robocopy` destinations). The conclusion drawn was architectural: predicting shell behaviour from
   command text is unwinnable, and a guard that keeps claiming to close the class becomes the
   "prose overstates code" defect this effort exists to remove. Redirected in Wave 1d to a
   deterministic Layer 1 integrity check.

## The incident that motivated S9

During Wave 1, a subagent truncated a **sealed** `discussions/**/events.jsonl` using `: > file` and
issued `DELETE` statements against `metrics/evaluation.db`. Both paths are in `PROTECTED_PATTERNS`.
No guard fired, because the validator is wired on the `Write|Edit` matcher while `Bash(*)` is in
`permissions.allow`.

**Verified damage: none to pre-existing history.** The record was agent-created the same day, never
committed (`git log --all` returns nothing for the path), and already superseded by a 35-event
transcription. Four mis-parsed findings rows from the superseded relay remain in Layer 2 and are
disclosed rather than deleted.

**Verified mechanism, measured after the fact:**
- Sealed files *are* read-only on disk (`IsReadOnly=True`) and were modified anyway.
- `grep -n "events.jsonl" scripts/quality_gate.py` → exit 1. The quality gate has **never**
  inspected Layer 1 integrity.

## Outstanding — carried, not closed

- **The preventive half of S9 is INERT** until `.claude/settings.json` gains a `PreToolUse` `Bash`
  matcher. That file is protected and is hand-applied by the developer. It must not be described as
  active protection until then.
- All four derived projects still carry the nine-principle numbering; the renumbered instruction
  layer must not propagate before they are reconciled.
- `dan_research_karpathy_wiki` carries `validate_tool_use.py` with **no `PreToolUse` block at all**,
  and `.git/hooks/pre-commit` exists in only 1 of 4 projects (the template's own copy is untracked,
  so it has never been able to propagate).

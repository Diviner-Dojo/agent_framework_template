# Review REV-20260523-065900 — `/distribute` framework capability

## Request Context
- **What was requested**: Review the newly-built `/distribute` capability before commit on branch `feat/distribute-command` (no push; developer merges).
- **Files/scope**: 5 `scripts/distribute/*.py` + `.claude/commands/distribute.md` + `tests/test_distribute.py`.
- **Developer-stated motivation**: Orderly "firmware-update" propagation of framework changes to derived projects without disturbing work-in-progress; involve the human only when risk can't be mediated; honors the Prime Objective's per-instance assent.
- **Explicit constraints**: opt-in HARD GATE; `pinned_traits` never overwritten; never push; never touch a target's main; fail-closed on ambiguity.

## Verdict: REQUEST-CHANGES

Four of five specialists returned request-changes; architecture-consultant returned approve-with-changes. The mechanical safety contract is **verified solid** — never-push (spy-tested), never-touch-main (sha-unchanged), pinned-never-staged, fail-closed preflight, strict `is True` opt-in, all-three-ref validation, honest ACE disclosure. The blocking gaps are: two cheap code bugs, one Prime-Objective-relevant classification blind spot the independent panel surfaced (and that the build checkpoints + test fixture shared), and owed governance documentation (an ADR + manifest-schema awareness).

> **The independent review earned its keep here.** Scenario A below was invisible to the three build-time checkpoints *and* to the green test suite, because the test fixture (`package_env`) constructs `target_baseline == hub_old` by construction — baking in the exact assumption that breaks in production. This is Principle #4 (independence prevents confirmation loops) working as designed.

## Blocking findings (must-fix before this is sound)

### B1 — Stale-baseline clobber misclassified as `value` (independent-perspective, verified)
`change_package._classify` ([change_package.py:249-266](../../scripts/distribute/change_package.py#L249-L266)) routes a file to `value` ("safe update") whenever the target's `drift_status` is `current` *or* `None`. But drift is computed against the **target's own mutable baseline DB**, not the hub–target common ancestor. A target that re-baselined *after* a local edit (or narrowed its `tracked_paths` so the file has no drift entry) gets its customization classified `value` — the **safest** category, shown with **zero human-visible detail** — and silently reverted on merge. This violates the Prime Objective tests (b)/(c). Frequency rises once v1.1's auto-re-baseline ships.
- **v1 mitigation (cheap, recommended now)**: surface per-file **diffs** (or at least paths + a clobber warning) for `value` files in the assessment doc — it's a local, confidential, human-only artifact, so confidentiality isn't violated. Right now `value` is the one category with no per-file detail and the one that can silently revert work.
- **v1.1 fix**: hub-side ancestor tracking (record the hub hash at the target's last adoption serial in `distribution_log`); classify `value` iff `target_current == hub_ancestor` (a real 3-way merge).

### B2 — `doc_relpath` validate-then-discard / re-resolve (security, verified)
[stage_branch.py:200](../../scripts/distribute/stage_branch.py#L200) validates `doc_rel` via `_resolve_within` then discards the result; [stage_branch.py:218](../../scripts/distribute/stage_branch.py#L218) re-resolves it *after* `checkout -b` mutated the tree (TOCTOU window). Fix: store the validated path and reuse it for the write.

### B3 — Unbounded accept/deny glob patterns from the manifest (security)
`accept_paths`/`deny_paths` from a target manifest flow into `fnmatch` with no length/char/count bounds ([change_package.py:144-150](../../scripts/distribute/change_package.py#L144-L150)). Add `_MAX_PATTERN_LEN`/`_MAX_PATTERN_COUNT` + null-byte rejection at load. (Self-DoS in the single-owner model, but cheap defense-in-depth.)

### B4 — `stage-for-manual-review` gate-bypass not self-documenting (security; the carried advisory, CONFIRMED)
`stage-for-manual-review` stages with `--no-verify` **and** skips the post-stage quality gate, but `distribute.md` does not mandate a visible gate-bypass warning on the staged assessment doc. A reviewer could see a branch that looks identical to a GREEN one. Fix: mandate a distinct "POST-STAGE GATE BYPASSED" header for that path + a `gate_bypassed: true` lineage field. (No code path lets it route to "ready" — the routing logic is sound; this is a self-documentation gap.)

### B5 — Missing ADR-0017 (architecture + docs-knowledge, both HIGH)
`/distribute` introduces hub→derived down-propagation that ADR-0003 explicitly **deferred** ("Phase 2+") and a new `custodian` manifest sub-schema. The rationale lives only in Layer-1 discussion `DISC-20260522-224424`. Per Principles #1/#5 it must become a searchable/supersedable ADR (consent model, classification taxonomy, v1/v1.1 split, single-owner ACE assumption; cross-ref ADR-0002/0003/0015; does not supersede 0003).

### B6 — Manifest schema awareness (architecture + docs-knowledge, HIGH)
`custodian.accepts_distribution` / `accept_paths` / `deny_paths` / `distribution_log` are read+written by code but absent from `manifest.py` validation and the `init_lineage` template. Seed `accepts_distribution: false` (+ empty path lists + comment) in `lineage_init`; add type-checks to `manifest_validate`; add a `custodian` comment block to the template manifest. Otherwise the 3 real targets hit `SKIPPED (opt-in absent)` with no reference for the undocumented flag.

# REV-20260609-052616 — Phase 3 Unit 1: Error-class grouping + remediation hints

## Scope

Phase 3 Unit 1 of SPEC-20260607-183136 (Telemetry & Oversight, ADR-0020):
the A2 Failure & Waste panel is refactored from a flat ranked list into
a triage view grouped by error class with a static remediation hint per
group. Net-new work on the retrospective panel path; live fragment
untouched (LiveCostEvent carries no structured failure_type, so the
live side is naturally retrospective-only).

**Files**:
- `src/telemetry/failures.py` — 7 spec classes + `OTHER` honest default;
  `ERROR_CLASSES` tuple; `REMEDIATION_HINTS` dict; pure
  `classify_error(signal) -> str` mapping by `failure_type` + first
  token of `signature` (NEVER reads `detail`).
- `src/telemetry/dashboard.py` — `_render_failures_panel` refactored
  into `_group_failures_by_class` + `_render_failure_class_group`
  helpers; new CSS (`.failure-class-group`, `.failure-class-header`,
  `.failure-class-count`, `.hint`).
- `tests/test_telemetry.py` — 16 new tests (classifier mapping,
  taxonomy + symmetric-hint pinning, panel grouping, honest-`other`
  rendering, escape defense, mixed priced+unpriced group sort).
- `memory/bugs/regression-ledger.md` — one new row, 16 test guards.

## Findings folded in-session

- **ux F1 HIGH (hint voice).** All 7 non-`OTHER` hints rewritten from
  engineer-imperative ("Verify the path...", "Correct the argument
  shape... before retrying") into manager-triage observation prompts
  ("These signals typically mean...", "The Detail column shows..."),
  dropping every "before retrying" — the manager-gatekeeper does not
  retry. `OTHER` hint kept (already in correct register; minor tweak
  to plural "These signals").
- **ux F2 MED (sub copy active).** Panel `<p class="sub">` rewritten
  from descriptive ("Grouped by error class, then ranked by wasted
  API-equivalent cost (most wasteful first)") to active navigation
  cue ("The most costly class appears first — start there. Within
  each group, signals are ranked by wasted API-equivalent cost").
- **ux F4 LOW (jargon in ORPHAN hint).** "tool_result" plumbing
  vocabulary removed; ORPHAN hint now says "never finished and
  returned to its main session" (manager-readable).
- **qa F1 MED (mixed-group sort coverage).** New
  `@pytest.mark.regression test_failures_panel_mixed_priced_group_outranks_pure_unpriced_group`
  pins that a not_found group with one priced + one unpriced signal
  outranks an orphan group with 10M unpriced wasted tokens — guards
  the `has_priced = any(...)` semantic in `_group_failures_by_class`
  against a future `all(...)` simplification.
- **arch F1 LOW (symmetric drift guard).** Two-prong fold: (a) new
  `@pytest.mark.regression test_remediation_hints_keys_match_error_classes_exactly`
  pins `set(REMEDIATION_HINTS) == set(ERROR_CLASSES)`; (b)
  `_render_failure_class_group` switched from
  `REMEDIATION_HINTS.get(cls, REMEDIATION_HINTS["other"])` silent
  fallback to fail-loud `REMEDIATION_HINTS[cls]` — a missing hint
  surfaces as `KeyError` rather than masquerade as `other`.
- **arch F3 LOW (sort key intent).** Added inline comment in
  `_group_failures_by_class.sort_key` documenting that
  `has_priced = any(...)` is intentional (so mixed groups still
  rank as priced) and that the `-unpriced_tokens` slot handles
  pure-unpriced groups structurally — "do not add an `if has_priced`
  branch here."

## Honesty discipline (ADR-0020) preserved end-to-end
- Classifier never reads `detail` (transcript-shaped natural language
  would invite a drifting regex heuristic).
- Bash retry loops stay `other` (regression-marked test).
- An unclassifiable `failure_type` stays `other`
  (regression-marked test).
- The `other` group renders with the same visual weight as a real
  class and surfaces its "do not fit a known class" hint
  (regression-marked test).
- The renderer no longer falls back silently when a hint is missing;
  a missing hint now raises `KeyError` at render time and the new
  symmetric-keys test catches the drift before it can ship.

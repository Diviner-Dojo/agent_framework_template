# Review REV-20260529-054131 — F2 verdict-boilerplate filter

## Request Context
- **What was requested**: Fix F2 (verdict-boilerplate pollution in the capture pipeline) per HANDOFF-20260528 / META-REVIEW-20260528 adjustment A′. Add a verdict/round-marker filter at the `extract_findings.py` extraction boundary so synthesis verdicts are not recorded as findings; add a regression test proving a verdict-line critique event yields 0 findings.
- **Files/scope**: `scripts/extract_findings.py` (new `_is_verdict_boilerplate` filter + wiring) and `tests/test_extract_findings_verdict_filter.py` (new). Other modified/untracked files are unrelated pre-existing work and out of scope.
- **Developer-stated motivation**: Verdict headers (e.g. `## Verdict: APPROVE WITH CHANGES (confidence 0…`) were being recorded as findings, polluting the findings corpus, the severity histogram, and the token sets fed to `mine_patterns` — causing phantom verdict-header promotion candidates across derived projects.
- **Explicit constraints**: Conservative filter (drop pure boilerplate, keep verdict-prefixed substantive lines); small-change workflow; do not push.

## Verdict: approve-with-changes

Both specialists returned approve-with-changes. The filter logic is correct (start-anchored `re.match`, ReDoS-safe, type-safe), the core regression contract is valid (would return 5 findings under the old code, 0 under the fix), and all 19 tests pass.

## Advisory findings

### A1 — Empty/whitespace summary not filtered (QA-F2, confidence 0.82)
`_is_verdict_boilerplate("")` returns `False`; an empty-`content` event therefore still writes a blank-summary finding (`severity=medium`, `category=general`). Pre-existing gap, not introduced here, but cheaply closeable. **Verified true.**
- **Fix taken**: Add `if not summary: continue` guard in the extraction loop + unit/e2e tests.

### A2 — `pass`/`fail` tokens absent from the test catalogue (QA-F3, confidence 0.78)
`_VERDICT_TOKENS` includes `pass`/`fail` and the predicate filters bare `PASS`/`fail`, but neither token appears in the test catalogue in either direction. **Verified true.**
- **Fix taken**: Add bare `PASS`/`FAIL` to the boilerplate catalogue and `"FAIL: …"`/`"Tests fail when …"` substantive cases.

### A3 — `_BARE_VERDICT_RE` under-drops `Approve: <prose>` (Sec-F1, Low, confidence 0.90)
A verdict token followed by a colon and trailing prose escapes the terminal anchor and is kept. This is the intended conservative trade-off ("do not over-drop"). `events.jsonl` is written by framework agents, so adversarial evasion probability is near zero — a data-integrity/quality note, not a security issue. **Verified true (intentional).**
- **Fix taken**: Document the trade-off in a comment beside `_BARE_VERDICT_RE`.

### A4 — Truncation-boundary interaction untested (QA-F4, Low, confidence 0.65)
A verdict header crossing the 200-char `_extract_summary` truncation is untested. The specialist notes start-anchored detection cannot be affected by tail truncation, so this is advisory only.
- **Disposition**: Added one cheap parametrized case for completeness.

## Security assessment (security-specialist, confidence 0.92)
- **ReDoS**: None. All four patterns are start-anchored, flat alternation of fixed literals, no nested variable-length quantifiers on overlapping classes; matched against a ≤200-char truncated summary → linear.
- **Type safety**: No `None` crash path — `_extract_summary` always returns `str`.
- **Other**: No secrets, SQL, subprocess, or path concerns. One trust boundary (`events.jsonl` → extractor), correctly sited.

## Strengths

- Correct wiring point (after `_extract_summary`, before classification).

- Exemplary test isolation (`tmp_path` + `monkeypatch`, FK row seeded, real schema via `init_db`); `@pytest.mark.regression` applied with the do-not-weaken notice.

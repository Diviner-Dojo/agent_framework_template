# Review: v4 reconciliation spec + ADR (rev 1)

Four reviewers, each in a context that never saw the generation reasoning, given the
artifacts and the risk to look for (Principle #3). Every claim relayed below was
**re-verified by the orchestrator against the repository** before being accepted — three
reviewer counts were themselves slightly off and are corrected here.

**Verdict: REVISE, 4/4.** The collision analysis and engineering dispositions largely
survived. The evidence apparatus did not.

## Blocking

### B1 — The spec's flagship measurement was taken against the wrong base
Converged independently by architecture and security. Rev 1 §3.3 reported v4's
`scripts/quality_gate.py` delta as **+50/−5** "vs the common ancestor". Verified:

```
git merge-base main claude/framework-modernization-opus-tr3ce9  -> af3fd10
git diff --numstat af3fd10 50e9d32 -- scripts/quality_gate.py   -> 123  5
git diff --numstat e4c8d73 50e9d32 -- scripts/quality_gate.py   ->  50  5
git merge-base --is-ancestor e4c8d73 main                        -> false
git diff --numstat af3fd10 c7bcc86 -- scripts/quality_gate.py   -> 929 50
```

The figure was measured against `e4c8d73` (public upstream), which is not an ancestor of
`main`. A document arguing "measured, not asserted" led with a mismeasurement, and built
its central rhetorical claim on it. **Disposition: corrected in rev 2 (§3.3); the claim
that base selection was settled by evidence is withdrawn.**

### B2 — "Orthogonal deltas" is false; a real duplicate function exists
Both trees independently added `check_promotion_backlog()` (main `:1035`, v4 `:504`),
absent from `af3fd10`; main's is a superset adding `_emit_warn_line`. Verified. The port
is not a mechanical three-way merge. **Disposition: rev 2 §3.3 + §6.1 name it as an
explicit which-version-wins decision.**

### B3 — The A/B task was not equivalent across trees, and the v4 arm had no instrument
QA falsified rev 1 §4.2's "byte-identical" claim. Verified by hash:
`assertion_store/embeddings.py` DIFFERS, `mcp_server/server.py` DIFFERS,
`tests/test_mcp_server.py` DIFFERS, `assertion_store/substrate.py` identical. v4 had
already fixed the eager-import bug that makes those tests skip on main, so the task was
strictly easier on v4 for reasons unrelated to the thesis.

Compounding: v4 has no `scripts/telemetry/`, no `stop_hook.py`, no
`metrics/model_call_log.jsonl` — the primary metric was unobtainable on that arm. And
neither tree's gate measures coverage for those directories, so "gate-green" was undefined
for the task, and defining it required editing the one file §4.2 forbade touching.
**Disposition: the A/B is withdrawn (rev 2 §4).**

### B4 — AC3 permitted a Stop-hook rewrite that drops a CLAUDE.md always-on invariant
Security. Rev 1 AC3 required only that "a Stop hook exists carrying both the ntfy flow and
the telemetry kick". A lean reimplementation injecting the raw ntfy reply satisfies that
completely, dropping the matched-choice-label allow-list. `tests/test_stop_hook.py` does
not exist on the v4 base, so nothing would catch it. ntfy topics are unauthenticated.
**Disposition: rev 2 AC3 makes the test file the specification.**

### B5 — The add-back writes into `.claude/hooks/`, which v4 hard-denies
Security. v4 added `.claude/hooks/` to `PROTECTED_PATTERNS` (the B5 remediation from
REV-20260728-140000). The reconciliation restores five hook files into that directory; the
cheapest unblock is deleting the pattern, re-opening arbitrary execution on every
`UserPromptSubmit` at the moment six hook paths are dangling. Rev 1's §3.2 asymmetry was
written one-directionally and did not protect v4's own enforcement.
**Disposition: rev 2 §3.2 + AC11.**

## Non-blocking, ranked

1. **"Evidence-gated" gated nothing** (independent-perspective, raised as blocking by that
   reviewer). No acceptance criterion was contingent on the A/B result; base selection was
   settled in §3.3 before §4 ran; R1 pre-declared "inconclusive" acceptable. The ADR named
   the risk in Consequences and shipped without closing it, which inoculates against the
   criticism rather than answering it. **Disposition: framing dropped, not repaired
   (developer decision); replaced by continuous instrumentation + named falsifiers F-A..F-D.**
2. **Wrong measurement site.** The A/B measured template-local work, against this repo's
   own recorded standard that hub artifacts are judged by derived-project usage. The three
   consumers were never consulted before the decision to replace their framework.
   **Disposition: acknowledged as R2; F-C moves the question to P6.**
3. **`--rebaseline` is not a lock.** Rev 1 §6.1 called it one. Verified: it is a
   `store_true` flag; consent lives in a docstring, argparse help, a warning printed *after*
   the baseline is rewritten, and a log field. It exits 0. A detective backstop exists
   (`_GATE_CONFIG_FILES` in `check_review_existence`) but only requires *some* review dated
   today. **Disposition: rev 2 AC2 — describe honestly as an audit trail, or implement and
   test a denial.**
4. **The unclassified remainder.** Rev 1 disposed of five collision surfaces plus the three
   items REV already caught. Verified: **25 files / 10,297 lines** exist under `scripts/` on
   main and not v4, including all of `scripts/telemetry/` (ADR-0020), which rev 1 never
   mentioned in any section including out-of-scope. **Disposition: rev 2 §6.6 (C6) + AC7 —
   per-file disposition, independently reviewed.**
5. **The third bucket's bound was unenforceable.** "An instrument must name its question" is
   a documentation requirement; a plausible question can be authored during the restoration
   that wants to keep the file. **Disposition: rev 2 R-B1/R-B2/R-B3 — the question must be
   traceable to a pre-existing artifact, the instrument must arrive with its test module,
   and the classification is independently reviewed.**
6. **RepoCademy's trust boundary is absent from the base.** No `scripts/education/`, no
   `gates.yaml`, no `CONTRACTS.md`, no ingest tests. Rev 1's AC5 ("one authority, one
   reader") could be satisfied by a writer other than the deterministic ingest — the exact
   alternative ADR-0029 rejected as a trust-boundary violation. **Disposition: AC5a/5b/5c.**
7. **§6.5 named the milder failure mode.** The patch does not fail cleanly — hunk #1 applies
   (stripping `statusLine`, the F1 instrument's display) and hunk #2 fails. And a missing
   `python scripts/stop_hook.py` exits 2, which for a Stop hook means block-stoppage plus
   stderr injected every turn — worse than a disarmed sensor. Six dangling hook paths, not
   five. **Disposition: rev 2 §6.5 + AC6 hook-path resolution check.**
8. **Missing test modules.** Verified **18** test modules present on main and absent from
   the v4 base (security said 19). **Disposition: AC9.**
9. **`PROTECTED_PATTERNS` is bypassable via `Bash(*)`** (`cp`, `sed -i`, `tee`, `python -c`),
   and `pre-push-main-blocker.sh` allows any `cd`-prefixed push by design — the same shape as
   the counter-evidence rev 1 cited. Pre-existing on both trees. **Disposition: recorded as
   R6 so §3.2 is not read as a stronger guarantee than the code provides.**
10. **ADR-0029 reference count.** Rev 1 said 13. Verified **23** files excluding sealed
    discussions, 24 including. **Disposition: rev 2 §6.3, AC4.**
11. **Counter-evidence sourcing asymmetry.** Supporting evidence carries named
    speakers/URLs; the counter-evidence (hook circumvention, `cd` bypass, output inflation)
    is uncited community report. **Disposition: rev 2 §2 weights it explicitly as
    unverified and rests the retention presumption on the on-repo B6 instance instead.**
12. **Transferability gap.** Anthropic ablated their own prompt against eval suites at
    product scale; this is a third-party layer on an already-ablated prompt with no eval
    infrastructure. **Disposition: rev 2 §2 states the limit.**
13. **`decision_makers` asserted a consensus that had not occurred** — rev 1 listed
    `[developer, steward]` on an unreviewed, unapproved ADR. **Disposition: rev 2 lists the
    developer only; the Steward gate has not run.**
14. **Legibility was never weighed.** ADR-0030's benefit is stated in line counts, against a
    PHILOSOPHY.md that explicitly disclaims lines-of-code as the measure, for a
    gatekeeper-developer whose comprehension is load-bearing for Principle #7.
    **Disposition: rev 2 R7 + the post-merge education gate.**

## Corrections to reviewer claims

- Architecture reported **24** main-only scripts; verified **25**.
- Security reported **19** missing test modules; verified **18**.
- Architecture and security both reported the ADR-0029 reference count as 24; verified
  **23** excluding sealed discussions (24 including them, but sealed discussions are
  immutable under Principle #5 and are not edited).
- Architecture's inference that the +50 figure came from dropping `check_promotion_backlog`
  (~75 lines) from the count was a reasonable hypothesis but incorrect; the actual cause was
  the wrong base ref (`e4c8d73`), which security identified precisely.

## Judgment call taken by the developer

Two directions were defensible and the choice was about ambition, not correctness:

- **Repair the evidence gate** (pre-registered threshold, reversal path, derived-project
  measurement site, counterbalanced N≈5–8 battery), or
- **Drop the evidence framing** and proceed on judgment, recorded as judgment.

**Developer decision, 2026-08-05: drop the framing.** Rationale accepted into the ADR: a
repaired experiment at this scale would most likely return "inconclusive" after weeks of
delay, buying false confidence rather than information, while the v4 branch goes further
stale. The sensor is retained as continuous instrumentation gating nothing, and four named
falsifiers (F-A..F-D) keep the decision revisable.

## Note for the record

The generator was confident, internally consistent, and wrong on two verifiable facts. Only
independent contexts that had not seen the reasoning caught them. This is the strongest
in-repo evidence available that the governance layer — specifically Principle #3 — should
not be thinned, and it is recorded in ADR-0031 as such.

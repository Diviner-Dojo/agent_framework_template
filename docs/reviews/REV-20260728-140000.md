# Review: framework v4 rebuild

Four reviewers, each in a context that never saw the generation reasoning —
given only the diff and the risk to look for (Principle #3). Every finding
below was reproduced or verified against the code before being recorded; the
verification command is named where it is not obvious.

**Verdict: REVISE.** The core is sound. The edges are not, and in this
framework the edges are where the guarantees live.

## What is sound

Confirmed independently by architecture and code review:

- The capture chain is single-entry, single-exit, and every downstream script
  has exactly one caller and one reason to exist.
- `assess_risk.py` and `briefing.py` are minimal and single-purpose — no
  premature layering, no interface with one implementation, no configuration
  for something nobody will configure. The scoring *logic* is correct; its
  git *interface* is not (A1–A4).
- `briefings` DDL is correct and idempotent, verified by drop-then-reinit.
- The `validate_tool_use.py` rewrite weakens nothing: 12 `SECRET_PATTERNS`,
  `PROTECTED_PATTERNS`, and `TEST_FILE_PATTERNS` verified identical by import,
  and 24 adversarial paths produce identical results in both versions. The
  removed locking was concurrency coordination, not a security control.
- The ntfy topic slug does not leak on any error path.
- The two self-reported over-deletions (ntfy loop, `surface_candidates.py`)
  are genuinely restored and wired.

## Blocking

### B1 — The education gate reports the wrong depth in the normal workflow

`scripts/assess_risk.py:collect_diff` with no flags runs bare `git diff`, which
is working-tree-vs-**index**, not vs HEAD. `.claude/commands/teach.md` invokes
exactly that form. Reproduced on an identical tree:

```
bare     : LIGHT  (score 0)
--staged : DEEP   (score 7)
```

Stage your work, run `/teach`, and the gate whose stated purpose is that depth
"cannot drift with model mood, session length, or how eager anyone is to ship"
reports LIGHT for a DEEP change. This defeats the central mechanism of the
change. Fix: `git diff HEAD`.

### B2 — New-file detection ignores the selected range

`assess_working_tree` always reads `git status --porcelain` regardless of what
range was diffed. Wrong in both directions: an unrelated untracked file scores
against a staged one-line README fix; and `--base e4c8d73` on this branch never
fires the new-source signal despite the range adding two new source files.
Fix: `git diff --diff-filter=A --name-only <range>`.

### B3 — Git failure is indistinguishable from "no changes", and fails toward less teaching

`_run_git` returns `""` on non-zero exit, missing git, or timeout. A bad
`--base` ref prints `LIGHT (score 0)`. "Assessment did not run" and "assessed,
low risk" produce identical output. This is the one result the tool must never
silently produce.

### B4 — `briefing.py` has no database guard and poisons the DB for other scripts

On a fresh checkout: `OperationalError: no such table: briefings`, the briefing
is lost, and a 0-byte `metrics/evaluation.db` is left behind — after which
`create_discussion.py`'s `DB_PATH.exists()` guard passes and it dies on
`no such table: discussions`. Reproduced. Every peer writer guards; this one
does not.

### B5 — `.claude/hooks/` is not protected, and `settings.json` points at five missing hooks

`PROTECTED_PATTERNS` covers `.claude/settings.json` but not `.claude/hooks/`.
Because the deletion left `settings.json` referencing five now-absent hook
files, writing `.claude/hooks/context-guard.sh` — a plausible "restore the
missing hook" action, and exactly what a prompt injection would request —
yields execution on every UserPromptSubmit without touching a protected path.
Before this change those files were tracked, so subverting one appeared as a
modification; now it is an innocuous new file.

Related: a missing `bash` hook exits 127 (fails open, harmless), but the
missing `python scripts/stop_hook.py` exits 2, which for a Stop hook means
block-stoppage and inject stderr into context every turn.

**Applying `docs/settings-v4.patch` is a merge blocker, not a next step.**

### B6 — `/apply-framework` moved four fail-closed guards from code into prose

Converged independently by architecture and security. The command went from 267
lines to 53, orphaning `scripts/distribute/` (2,375 lines, only caller deleted):

| Lost its invoker | What it enforced |
|---|---|
| `assessment.wrap_data_only` | prompt-injection framing on files read from a **target** repo |
| `assessment.redact_secrets` | fail-closed scrub before target text enters a written doc |
| `repo_safety_check.apply_assent_preflight` | Prime Objective per-instance human assent |
| `repo_safety_check.check_clean_tree` | clean-tree precondition |

The agent holds Write and `Bash(*)` on both repos and is about to branch and
copy files into the target. This happened in the same commit whose
`FRAMEWORK.md` states that a prose guarantee is a request. `scripts/lineage/`
(967 lines) is orphaned the same way.

Also: `apply-framework.md:32` says copy `.claude/`; `:52` says never modify a
target's `.claude/settings.json`.

### B7 — `/decide` emits an ADR the quality gate rejects

`decide.md` produces `id:`, omits `decision_makers`, and writes
`## Alternatives`. `quality_gate.py:131-137` requires `adr_id`,
`decision_makers`, and `## Alternatives Considered`. The framework's primary
governance workflow has no path to completion. The gate's spelling is what 29
existing ADRs use, so the template should move.

### B8 — Nine ADRs assert accepted decisions that no longer describe the system

ADR-0013, 0016, 0018, 0020, 0021, 0023, 0024, 0026, 0028 all read
`status: accepted` with implementations deleted. `ADR-0029:9` has an empty
`supersedes:`. Principle #4 exists to keep the decision record truthful; the
commit that restates it breaks it. Cheapest item here to fix and the most
expensive to leave, because it is what a future reader will trust.

### B9 — Three live ledger-guarded regression tests are silently disabled

The `importorskip` guards skip `test_mcp_server.py` and `test_substrate.py` as
whole modules, disabling `TestThreadLocalIsolation` (named by name in
`CLAUDE.md`) and two path-traversal guards — while the gate still prints
`16 guard(s)`, because it only checks that the test *file* exists. Root cause
is the eager module-scope import at `assertion_store/embeddings.py:14`, which
contradicts that module's own docstring. Deferring it into `embed()` restores
all three with no extras installed.

## Non-blocking, ranked

1. **The framework severed its own feedback loop.** `record_yield.py` was the
   only writer to `protocol_yield`, which `compute_agent_effectiveness.py:26`
   still reads — `findings_false_positive` is now permanently 0 and confidence
   calibration is systematically flattering. `ingest_token_usage.py` was the
   only writer to token totals, so `v_token_efficiency` (`init_db.py:380`) is
   permanently empty. The `briefings` table has no outcome column, so
   ADR-0029's own stated falsification plan cannot execute. `/retro` retains an
   explicit deletion prior with no surviving instrument that could contradict
   it. Not intent — structure: measurement was classified as telemetry, and
   telemetry as scaffolding.
2. **A third over-deletion: `audit_calibration.py`.** Its docstring describes
   itself in ADR-0029's governance vocabulary, written before ADR-0029 existed
   — writes proposals to a human-approved queue, never edits a classifier
   surface. Governance by the ADR's own test, deleted as scaffolding. The
   implication is that directory membership did some of the sorting the
   principle was credited with.
3. **The regression ledger contains false linkage.** Rows repointed to
   `tests/test_init_db.py` name three test functions that do not exist there.
   The gate never checks named functions, only files.
4. **`_is_retired` retires on rename.** `git mv mcp_server/server.py …` retires
   three live guards whose bug-carrying code is alive at the new path.
   Malformed `file` cells (backticks, commas, literal `+`) also fail open.
5. **`_has_application_code` is untested** and misses a `src/__init__.py`-only
   layout. `assertion_store/` and `mcp_server/` (727 lines) have never been
   measured by the gate.
6. **`assess_risk` porcelain parsing** misses C-quoted paths (spaces,
   non-ASCII) and collapses a new untracked package to one entry; `DOC_EXT`
   guards only the security signal, so ADR prose fires the schema signal.
7. **Stale documentation.** `docs/CAPTURE_PIPELINE.md` is a `CLAUDE.md` pointer
   and describes v3. `docs/FRAMEWORK_SPECIFICATION.md` (1,557 lines) maps 12
   agents and 25 commands. 3,300+ lines total.
8. **Dead schema and advisories.** Five tables with zero readers and writers;
   `check_promotion_backlog` recommends a deleted `/promote`;
   `_FRAMEWORK_PREFIXES` lists deleted `.claude/rules/` and omits
   `.claude/skills/` and `.claude/hooks/`.
9. **`close_discussion.py:115`** prints advice to run a deleted script, on
   every close.
10. **`pyproject.toml:3`** still `version = "3.5.0"`; per-file-ignores name
    four test files that no longer exist. Orphans: `backup_utils.py`,
    `ingest_reflection.py`, `spawn_project.py`, `config/model_context_profiles.yaml`.
11. **The gate's definition of code is self-inconsistent** — `scripts/` counts
    as reviewable code but sits outside format, lint, and coverage, while the
    README headlines ≥80%.

## Corrections to reviewer claims

- Security reported the archived `BUILD_STATUS` account details (`$666.26`,
  `"Dan's Individual Org"`) as newly entering git history. **Not introduced
  here** — present since commit `a12a090`. The finding still stands as a missed
  opportunity: resetting that file was the moment to stop carrying it forward.
- Contrarian framed the whole change as unmeasured. Fair for the cost claim;
  the instruction-conflict argument does not depend on measurement. The
  permanent loss of the ability to compare v3 to v4 is real.

## Judgment calls for the developer

Two blocking items have no correct answer the reviewers can supply, because
both directions are defensible and the choice is about scope, not correctness:

- **B6** — rewire `/apply-framework` onto `scripts/distribute/`, or delete the
  package and supersede ADR-0021 saying the cross-repo path was retired.
  Leaving fail-closed code with no caller is the one option that is wrong.
- **Non-blocking 1 and 2** — restoring the two ingesters and
  `audit_calibration.py` partly re-inflates what the rebuild set out to cut.
  The alternative is accepting that "was v4 better than v3?" is permanently
  unanswerable.

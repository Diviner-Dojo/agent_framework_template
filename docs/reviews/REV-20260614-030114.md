## Summary

The corpus-respects-gitignore fix (ADR-0025) re-points the framework corpus enumerator at
git's exclusions: `collect_framework_files` now lists tracked files via `git ls-files -z`
(with a non-git `rglob` + denylist fallback), and `greenfield_offer_set` converts the
previously-silent cap-truncation and empty-corpus cases into fail-loud `ValueError` /
`warnings.warn`, plus a new `list_untracked_framework_files` that warns about framework
work that won't propagate until committed. All three specialists found the implementation
correct, well-documented, and consistent with ADR-0025. **Zero blocking findings.** The
only changes recommended are non-blocking test-hardening on the newly-introduced fail-loud
error branches.

## Findings by Specialist

- ADR-0025 §1–5 map one-to-one onto the code; the ADR was read first and is consistent with the
  implementation, including the subtle points (resolve-root injection guard, NUL-split rationale,
  fail-loud-after-positive-probe vs fail-soft-on-probe).
- **Upstream-of-B1 verified structurally**: nothing in `_utils.py` or `greenfield_offer_set`
  touches `_classify` or the `value-unverified` floor — the change only alters *which keys enter
  the corpus*.
- **Contract-unchanged verified**: all 4 callers consume `dict[str, str]` unchanged
  (`change_package.py:539`, `router.py:107`, `drift.py:112`, `init_lineage.py:158`); the new
  `list_untracked_framework_files` is consumed only at the apply layer (`change_package.py:555`).
  The sibling-function seam genuinely contains the blast radius.
- **Right layer (Principle #8)**: the shared-util fix closes the bug class for all 4 callers; the
  ADR records why the per-caller fix was rejected.
- Advisory: dual-path drift surface between the git exclusion and the `_is_framework_junk`
  denylist — mitigated by `test_git_path_and_fallback_yield_same_key_set`, but that test only
  covers a junk-free tree. Low: `_is_framework_junk` hardcodes hub-specific literals (acceptable,
  YAGNI). Prime Objective: cleared.
- Confidence: 0.88

### Security Specialist — approve (adversarial)
- Core threat surface — argument injection and output smuggling across the subprocess boundary —
  is correctly mitigated. Explicitly cleared: argument injection (`resolve()` + list-args +
  `--` separator + `shell=False`); output smuggling (NUL-split verified live with a payload);
  path traversal (`ls-files` emits repo-relative paths only; file-level symlink read is
  hub-admin-trust; pre-existing `TestReadTextSymlinkGuard` covers the read/diff path); backslash
  normalization (applied before the predicate, not bypassable); timeout (`_GIT_TIMEOUT=15` on both
  calls); `errors='replace'` decoding; force-fallback-via-probe-failure (only `OSError`/`Timeout`
  trigger fallback, not contributor-manipulable).
- Advisory F1: the leading-dash guard (`_utils.py:207`) is platform-**vacuous on Windows** —
  `Path.resolve()` prepends a drive letter, so `startswith("-")` is never True on `win32`
  (the guard is correct + needed for a future POSIX port; dead on the current platform).
- Advisory/speculative F2: the NUL-split (`-z`) contract is correct but flag-dependent and guarded
  only by a comment; a structural test would lock it.
- Prime Objective: cleared — no new extraction vector.
- Confidence: 0.91

## Recommended Improvements (Non-Blocking)

Ranked test-hardening on the newly-introduced fail-loud behavior (cheap, aligns with the fix's
stated fail-loud intent):

1. Add tests for the two fail-loud `RuntimeError` branches in `_git_ls_files`
   (`_utils.py:83-86`) — patch `subprocess.run` to raise `TimeoutExpired` / return `returncode=1`
   *after* a positive `_is_git_repo` probe. (qa F1)
2. Add a POSIX-only (or mocked-`resolve()`) test for the `_resolve_root` flag-injection guard
   (`_utils.py:207-208`), **and** document that the guard is platform-vacuous on Windows
   (drive-letter prefix). (qa F2 + security F1 — same guard, merged)
3. Add a structural NUL/newline test: a path containing `\n` through the split asserts a single
   entry, locking the `-z` contract against a future maintainer dropping `-z`. (security F2)
4. Add a POSIX-only symlink/`is_file` silent-drop test for the git path (`_utils.py:166`). (qa F3)
5. Add a drift/init-level gitignore-exclusion regression test so caller coverage is deliberate,
   not incidental. (qa F5)
6. Add a clarifying comment that `test_git_path_and_fallback_yield_same_key_set` is clean-tree
   scope; consider a future parametrized junk-shape test feeding the git path (dual-path drift
   guard). (qa F4 + arch F1)

No-action note: `_is_framework_junk` hub-literal coupling is acceptable (YAGNI) — flagged as
where future hygiene shapes accrue (arch F2).

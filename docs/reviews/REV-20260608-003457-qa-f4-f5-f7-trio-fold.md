# REV-20260608-003457 — qa F4 + F5 + F7 trio fold (Layer B Phase 1 advisories)

## Scope

Tests-only fold of three cohering qa-specialist advisories from REV-20260607-200447, all targeting `tests/test_dashboard_server.py`:

- **qa F4 — CI portability.** The existing AC3 byte-stability guard (`test_routes_leave_hooks_and_settings_byte_unchanged`) used `pytest.skip` when `_REPO_ROOT/.claude/{hooks,settings.json}` were absent. On a CI checkout without the `.claude/` tree the load-bearing AC3 *behavioral* guard ran zero assertions and silently passed.
- **qa F5 — CORS preflight negative guard.** The production CORS surface (`allow_origins=[f"http://{HARDCODED_HOST}:{port}"]`, `allow_credentials=False`) had no machine-enforced regression test against a future flip to a wildcard.
- **qa F7 — retrospective Exception branch.** `retrospective_fragment` catches `sqlite3.OperationalError` as 503 and bare `Exception` as 500; only the OperationalError path had a regression test. The bare-Exception 500 branch was un-pinned.

Production code was NOT modified in this session — these are pure coverage additions guarding contracts that already hold.

## Files touched

- `tests/test_dashboard_server.py` (modified):
  - `test_routes_leave_hooks_and_settings_byte_unchanged` — sandbox rebuilt synthetically in `tmp_path` (two stub hook scripts + stub `settings.json`); conditional skip removed; unused `shutil` import auto-cleaned by ruff.
  - New `test_retrospective_error_general_exception_response_is_generic` (`@pytest.mark.regression`) — monkeypatches `assemble_dashboard_data` to raise `RuntimeError`, asserts 500 + neither the marker, the class name, nor `Traceback` appears in the body.
  - New `test_cors_preflight_from_foreign_origin_emits_no_allow_origin_header` (`@pytest.mark.regression`, parametrized over `["http://evil.example.com", "http://127.0.0.1.evil.example.com"]`) — OPTIONS preflight with foreign Origin + `Host: 127.0.0.1:8765` to bypass HostHeaderGuard; asserts `Access-Control-Allow-Origin` header is ABSENT and `Access-Control-Allow-Credentials` is not `true`.
  - Existing `test_error_response_is_generic` tightened from `assert r.status_code in (500, 503)` to `assert r.status_code == 503` (qa F4 fold, low-risk in-scope cleanup paired with the new 500 test).
- `memory/bugs/regression-ledger.md` — +1 entry under the table (classified Trust Boundary Gap), listing all three test functions.

- **security-specialist**: APPROVE-WITH-CHANGES, 0.91. 2 MED + 1 LOW + 2 INFO. Both MED findings (subdomain-spoof origin + Allow-Credentials assertion) folded. LOW Finding 3 (simple GET cross-origin coverage) deferred as advisory (theoretical under single-middleware architecture).

## Convergence

Both panellists independently identified the qa F5 CORS test as the weakest of the three new guards. Both proposed strictly compatible improvements: qa-specialist pushed for the precise header-absent contract (`allow_origin == ""`); security-specialist pushed for the subdomain-spoof origin and the credentials check. The folded test integrates all three improvements as one parametrized test with a header-absent assertion and a credentials assertion — strictly stronger than either reviewer's individual proposal.

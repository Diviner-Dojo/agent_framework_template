## Summary

Reviewed the defect-C (gate-log integrity) fix: `scripts/quality_gate.py` no longer
logs a clean `overall: "pass"` when checks were skipped. `_log_outcome` is split into a
pure, testable `_build_outcome_record`, and `overall` now has three honest states —
`pass` (all ran + passed), `pass_with_skips` (any `--skip-*`, including the vacuous
all-skipped case), `fail` (a ran check failed) — plus a new `skipped_count` field and an
honest console summary. Both specialists confirm the code fix is **correct and complete**:
the three-state logic is exhaustive, mutually exclusive, correctly priority-ordered, and
the regression test is a valid guard. **0 blocking, 8 advisory.** The advisories are doc-sync
and test-strengthening items that serve the fix's own intent (honest trend analysis only
pays off if consumers know about `pass_with_skips`); all are being applied before commit.

## Request Context

- **What was requested**: Fix defect C (gate-log integrity) from META-REVIEW-20260528 — `quality_gate.py` could log `overall: "pass"` to `metrics/quality_gate_log.jsonl` while individual checks were skipped, a Principle #2 (honest capture) violation. Make the log reflect what actually ran.
- **Files/scope**: `scripts/quality_gate.py`, `tests/test_quality_gate.py`; regression-ledger entry added.
- **Developer-stated motivation**: Capture must be honest; the meta-review queries this log for pass/fail trends, so a skipped/vacuous run reading as a clean pass corrupts trend analysis.
- **Explicit constraints**: "new `overall` state + `skipped_count`" design; exit-code semantics must NOT change (`--skip-*` is a deliberate allowed bypass that still exits 0); keep `pass`/`fail` backward-readable.

## Findings by Specialist

### QA Specialist
- Confirmed three-state logic is exhaustive/mutually-exclusive and priority-ordered (fail checked before pass_with_skips). `results`/`_CHECK_NAMES` index alignment verified for the coverage-skipped scenario. Regression test is a genuine guard (old `pass if passed==total` returns `pass` for passed=5/total=5).
- Advisories: (1, Med) missing edge-case tests — multiple simultaneous failures and a skip of the **last** check (regression, idx 6), which alone exercises the `idx < len(results)` boundary; (2, Low) `passed`/`total` are caller-computed not derived from `results` — undocumented contract; (3, Low) regression test only spot-checks `checks['format']`, should assert post-skip checks (`regression`/`adrs`) for index-alignment confidence; (4, Low) the 7 `skip_*` attr strings are duplicated across 3 sites — extract a constant (REVIEW.md rule 4).
- Confidence: 0.91

### Docs-Knowledge
- `_build_outcome_record` docstring is exemplary and authoritative; regression-ledger entry is the most thorough in the ledger (incl. the cache-exoneration ruling).
- Advisories: (1, Med) `docs/CAPTURE_PIPELINE.md:23` documents the log but gives no schema — consumers querying `overall == 'pass'` will silently under-count `pass_with_skips`; (2, Med) `CLAUDE.md:70` cache Known-Limitation may be misread as implying the cache pollutes the log — append a one-sentence exoneration; (3, Low) `.claude/commands/meta-review.md:196` "query for pass/fail trends" is now underspecified — name the 3 values, count `pass_with_skips` separately; (4, Low) module docstring could note skip→`pass_with_skips`.

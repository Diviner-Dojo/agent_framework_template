## Recommended Improvements (high-priority — fix in same commit or immediately after)

These three are **convergent across 2+ specialists** and matter for Howie's clean inheritance:

1. **UI-files dispatch trigger sync** (arch + docs convergence).
   - `facilitator.md` has: `Any change touching UI files (3+ files) → ux-evaluator`
   - `review_gates.md` only has: `UI/UX with accessibility concerns → ux-evaluator, qa-specialist`
   - **Fix**: Add the 3+ files quantitative trigger to `review_gates.md`'s Domain Specialist Triggers table as a distinct row, AND mention it in CLAUDE.md's Review Activation section. Howie will have UI files — this trigger needs to fire predictably.

2. **CLAUDE.md educator roster line is stale post-ADR-0012** (docs).
   - Current ([CLAUDE.md:52](CLAUDE.md#L52)): `educator | sonnet | The Coach — walkthroughs, quizzes, mastery tracking`
   - **Fix**: `educator | sonnet | The Coach — decision-maker walkthroughs, Bloom-grounded quizzes, S/I-Tier mastery tracking (ADR-0012)`
   - A developer setting up Howie reads CLAUDE.md first; the audience recalibration (decision-maker, not developer) is material and currently invisible there.

3. **`completed_commit` / `completed_at` lifecycle reference** (qa + docs).
   - plan.md introduces both frontmatter fields. build_module.md has an inline note about `completed_commit` being deferred to post-commit. No central doc explains the cross-command lifecycle.
   - **Fix**: One sentence in CLAUDE.md's Commit Protocol section (or near the Directory Layout `docs/sprints/` entry): "`completed_at` is set at build completion; `completed_commit` is populated post-merge when the SHA is available."

## Other Advisories (lower priority)

4. **Bloom's question mix contradiction** (qa). `educator.md` specifies 30% Understand/Apply + 70% Analyze/Evaluate/Create. `review_gates.md` specifies 60-70% Understand/Apply + 30-40% Analyze/Evaluate. Resolution: update `review_gates.md` to match the educator.md reframe (which is ADR-0012 territory), OR explicitly note that educator.md is the authoritative source for quiz composition.

5. **review.md Step 7d PR_NUMBER threading** (qa). The eligibility check in Step 0.5 emits `ELIGIBLE: PR #<number>` but Step 7d's shell template has `PR_NUMBER` as a literal placeholder. Either add explicit threading instruction OR re-derive in Step 7d: `gh pr comment $(gh pr view --json number -q .number) --body ...`

6. **facilitator.md "UI files" undefined** (qa). The trigger fires on "3+ UI files" but the term has no definition in this template's Python/FastAPI stack. Either constrain with a file-extension list (`*.html, *.css, *.js, *.tsx`) or add a forward-looking note that it activates when a frontend layer exists.

7. **educator.md mastery dimensions in YAML output** (arch). The Output Format names `strategic_mastery` and `implementation_mastery` but `record_education.py` does not store these. Acceptable today; flag for a future ADR if you want mastery progression queryable in Layer 2.

8. **educator.md hard dependency on `memory/projects/*.md`** (arch, info). Fine for this template (both directories populated). Derived projects without analyses yet may want a fallback ("if no analyses exist, lean on ADRs alone").

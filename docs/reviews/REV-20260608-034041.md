## Findings by Specialist

### QA Specialist
- **Finding 1 (MED — FOLDED in-session)**: Subagent uncosted per-event flag has no direct test — the three new regression tests fire on main-lane only. `_apply_message` forks at `lane_id == "main"`; both branches reach the same unified `LiveCostEvent(...)` constructor today, but a future refactor splitting the constructor call into the two branches could break the subagent path without triggering any new test. **Fold**: extended `test_subagent_lane_with_unknown_tier_model_is_uncosted` to additionally assert `state.recent_events[-1].uncosted is True` AND `lane_id == "tool_x"` on the non-main branch; promoted the test to `@pytest.mark.regression`.
- **Finding 2 (LOW — DEFERRED-AS-ADVISORY)**: Strengthened shape test's `isinstance(uncosted, bool)` only exercises the False branch in that specific test. The True branch is covered end-to-end by the dedicated `test_render_per_turn_cost_chart_panel_payload_carries_per_event_uncosted_flag` test, so there is no gap in overall coverage. Specialist explicitly notes "no change required." Deferred.
- **Finding 3 (LOW — DEFERRED-AS-ADVISORY)**: Failure-kind `LiveCostEvent` default `uncosted=False` has no explicit dedicated test. Non-risk because (a) the dataclass default enforces it, (b) the renderer filters failure events before the payload is built, and (c) the existing `test_render_per_turn_cost_chart_panel_filters_failure_events_out_of_payload` would catch any leakage. Specialist explicitly notes "no action required." Deferred.
- Confidence: 0.88

### Architecture Consultant
- **Finding 1 (LOW — FOLDED in-session)**: Aggregate-vs-per-event invariant is eventually-consistent, not strict. The invariant `sum(ev.uncosted for ev in state.recent_events if ev.kind=="turn") == state.uncosted_turns` holds ONLY while fewer than `RECENT_EVENTS_CAP=100` turn events have been folded; after the rolling-window slice, the per-event tally drifts below the aggregate counter — by design, but not stated. A future consumer computing a per-event uncosted ratio from `recent_events` (a plausible "% partial coverage in recent activity" widget) would silently disagree with `uncosted_turns` once a session exceeds 100 turns. **Fold**: extended `LiveState.uncosted_turns` docstring with the explicit session-cumulative vs rolling-window distinction.
- **Finding 2 (INFO — FOLDED in-session, option a)**: Schema-evolution clause on `_ChartPoint` has an unfulfilled forward obligation. The clause "adding a field is non-breaking IFF the init script treats unknown fields as opaque" is load-bearing for the safety of this fold, but the init script does not exist yet (Phase 2 step 4, CSP-blocked). The IFF condition is therefore a forward obligation on the upcoming init script slice, not a property established by commit `bd9798c`. Specialist offered two options; the developer chose (a). **Fold**: extended the `_ChartPoint` docstring with one parenthetical noting the Phase 2 init script MUST treat unknown fields as opaque (forward obligation, currently CSP-blocked).
- Confidence: 0.93

## Summary

Multi-agent review of the ADR-0028 goal-loop reliability hardening (safety-critical control-flow;
backflow from VerificationPortal first-use). All three specialists return **approve-with-changes** and
agree the **core design is sound**: the always-skeptic is genuinely independent (`model.judge`, never the
builder's verify command) and fail-closed (red → PARK, no self-green); protected_paths fails closed; H2
branch protection is defense-in-depth; and the new tests are revert-proof (the seam-2b test genuinely
fails on the old `check`-based code). The quality gate is 7/7 (236 tests). Two HIGH findings (from the
independent reviewer — the Principle-#4 payoff) must be resolved before merge, one of which contains a
**developer design decision** that was surfaced and is pending.

## Findings by Specialist

### Security-Specialist (0.86, approve-with-changes)
- All five required safety guarantees verified **sound** (independence, fail-closed, seam-2b protocol +
  allow-list, protected_paths fail-closed, H2, test-fails-on-old-code).
- **[Medium] seam-2b latency:** the real `collab_loop poll` is `while True:` and never exits on match, so
  `subprocess.run(timeout=3600)` blocks the full hour on every gated tick. The approval is **not dropped**
  (captured via `TimeoutExpired.stdout` + `flush=True`), so correctness-safe — but it undercuts the AFK
  value proposition. Fix: an `--exit-on-match` / bounded `poll` that returns promptly.
- **[Low, pre-existing] prompt injection:** `delta.added_lines` is interpolated unfenced into
  `judge_prompt` (the always-skeptic reuses this path). Not new to ADR-0028; follow-on hardening (fence
  like `anchor_context`).

### QA-Specialist (0.92, approve)
- 236 pass; **every** ADR-0028 guard has a revert-proof test; seam-2b (4 assertions) and B3 FlipVerifier
  are the strongest in the suite; H2/protected_paths well-parametrized; 2a bind-shape revert-proof.
- **[Low nits]** make the B3 veto causation explicit (`max_iterations=99`); assert `modes == ["ask","poll"]`
  ordering; comment the two permissive validate tests.

### Independent-Perspective (0.83, approve-with-changes)
- **[HIGH] Finding 1 — skeptic-veto semantics + dead `_backstop_only`:** the veto path
  (`goal_loop.py:965`) goes straight to `_finish(PARKED)`, but `_backstop_only`'s docstring (576-581) says
  *it* decides park-vs-keep-building on a veto → dead code on its intended path, AND a single stochastic
  `llm-judge` red **terminally strands a legitimately-complete run**. Contains a genuine design fork
  (Retry consult-ladder / Park terminal / Human adjudicate-at-goal-met-gate). **Surfaced to the developer
  (AFK); awaiting decision.** "Do not ship with code and docstring disagreeing."
- **[HIGH] Finding 2 — seam-2b test fidelity:** the transport's happy path is only tested against a fake
  runner that returns instantly, a path the real (never-exiting) `poll` cannot take; the gate hinges on
  `subprocess` timeout-stdout salvage (a CPython detail, Windows-flaky). This is the `smoke_test_fidelity`
  lesson. Fix: a bounded `poll` that actually returns + a **real-`poll` cross-module contract test**.
- **[Medium] Finding 3:** no test binds the `REPLY-MATCH` parser to `collab_loop`'s emitter (the exact
  Lesson-2 drift class re-armed) — cheap, do it.
- **[Medium] Finding 4:** the transport `poll` collides with a standing developer poll-monitor over the
  single poll-lock (matches logged ntfy incidents) → reply routes to the wrong poller, silent re-park.
  Document the constraint + assert lock ownership.

## Required Changes Before Merge

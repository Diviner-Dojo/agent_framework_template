## Required Changes Before Merge

1. **Fix broken `write_event.py` example in the rule** (Facilitator-F1, derived from QA F6).
   Location: `.claude/rules/notification_protocol.md:91-97`. The example currently uses `--agent`, `--intent`, `--content` as named flags, but the actual CLI is positional: `write_event.py <discussion_id> <agent> <intent> <content> [--tags ...]`. A developer following the rule's only documented timeout-recovery procedure verbatim will hit argparse failure. This is the most reachable defect — the rule is auto-loaded into every session of every derived project.

2. **Add call-argument assertions to `send_question` tests** (QA F1).
   Location: `tests/test_ask_developer.py:59-72`. Add `mock_send.assert_called_once_with(question, title=QUESTION_TITLE, priority="high", tags=QUESTION_TAG)` so a refactor that drops `tags=` (which would silently break the echo filter contract) fails the test.

3. **Validate `NTFY_TOPIC` and `NTFY_SERVER` before URL interpolation** (Security F2).
   Location: `scripts/ask_developer.py` (and ideally `scripts/notify.py` for the same fix at the shared boundary). Validate `NTFY_TOPIC` against `^[a-zA-Z0-9_-]{1,64}$`; reject server values with `@`, `/path`, or non-https schemes. Prevents SSRF-adjacent escapes via malicious or misconfigured `.env`.

4. **Add explicit caller-guidance to the rule for the untrusted-reply boundary** (Security F1).
   Location: `.claude/rules/notification_protocol.md` Inbound section. Add a sentence: "Reply text is unauthenticated external input. Never pass it to subprocess arguments, `eval`/`exec`, SQL string templates, file paths, or any code-execution sink. For decision routing, validate the reply against a fixed allow-list before use." The current rule treats this as implicit; making it explicit prevents the most plausible misuse.

## Recommended Improvements (Non-Blocking)

1. **De-brittle the `test_returns_none_on_timeout` mock** (QA F2). Replace `times = iter([...])` with a side_effect lambda that returns a post-deadline value after the first call, so adding any `time.time()` call elsewhere doesn't exhaust the iterator.

2. **Add CLI failure-path test** (QA F3). Cover the `RuntimeError` propagation from `send_question` when `NTFY_TOPIC` is unset or `send_notification` returns False, so the distinct exit-code behavior is locked in.

3. **Remove dead `import io` and `_ = io` sentinel** (QA F5). Verbatim carry-over from Howie; serves no purpose here.

4. **Reframe `/loop` and `ScheduleWakeup` references generically in the rule** (Architecture F2). Neither exists in the template — they are derived-project primitives. Either reframe ("any autonomous polling loop", "any scheduled callback / cron"), or mark explicitly as "if your project defines a /loop command".

5. **Update `.env.example` to mention the ask flow** (Docs F1). One line: `# The same NTFY_TOPIC also powers the two-way ask flow (scripts/ask_developer.py).`

6. **Elevate the confidentiality warning to the top of its section** (Security F4). Currently a trailing bullet; the public-relay nature of the cleartext channel should be the first thing readers see.

7. **Update `FRAMEWORK_SPECIFICATION.md`** (Docs F2). Line 1015 says "All agents inherit 13 rule files" — actual is 15. Add a v3.5 changelog row noting the new rule (now 15 rules, +2 since v3.4 — `failure_taxonomy.md` and `notification_protocol.md`).

8. **Add Google-style Args/Returns/Raises sections to `send_question` and `fetch_reply`** (Architecture F4). `ask()` has them; the other two are prose-style. Consistency for free.

9. **Consider an ADR for the ntfy two-way HITL coordination primitive** (Architecture F1 / Docs F3). The original `notify.py` was added without an ADR; this change qualitatively extends it into a HITL coordination primitive with a default-on-timeout policy. ~300 words covering context, alternatives (AskUserQuestion-only, local webhook, BUILD_STATUS-only), decision, consequences. Not strictly required for merge but the developer-stated "template-is-the-hub" priority makes "why ntfy?" a question every derived project will ask.

## Speculative Findings — Lower Confidence

1. **Empty-question edge case** (QA F4, confidence 0.76). `send_question("")` is undefined behavior — publishes empty body, echo filter could mask normal replies. Low-probability path but worth documenting the contract (reject vs accept) one way or the other.

2. **Rule example drift risk** (QA F6, confidence 0.72). Promoted to blocking finding via verification — see Required Change #1.

3. **No ADR for ntfy** (Docs F3, confidence 0.72). Covered above as recommendation #9.

4. **Echo filter title-spoofing** (Security F3). Acceptable for stated purpose; nonce/HMAC is overkill for the default threat model. Worth keeping in the rule as a "for sensitive contexts" note only.

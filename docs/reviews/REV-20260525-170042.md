## Summary

Reviews workstream 1 of replicating agentic_journal's push-notification
methodology: an opt-in `--notify` flag and `_notify_outcome` helper on
`scripts/quality_gate.py` that fires a best-effort ntfy push with the gate
result, plus a new test file, a skill-doc section, and a `type:vision` doc for
the deferred watcher (context only). The change is a clean, minimal, opt-in
egress addition. Security found zero blocking issues (confidentiality is safe by
construction — only integer counts cross the boundary; never-crash contract
holds). QA found one blocking test-quality defect (a vacuous assertion) and three
advisory items. **Verdict: approve-with-changes** — fix the one blocking finding
before commit.

## Request Context

- **What was requested**: Replicate the agentic_journal push-notification
  methodology into the framework template without downgrading the template's
  better implementations. Workstream 1: task-boundary notification hooks. The
  deferred watcher is captured as a `type:vision` doc, not built.
- **Files/scope**: `scripts/quality_gate.py`, `tests/test_quality_gate.py`,
  `.claude/skills/notifying-the-developer/SKILL.md`, and the watcher vision doc.
- **Developer-stated motivation**: The framework should benefit from the derived
  project's methodology, but not at the expense of its own where the template's
  version is better.
- **Explicit constraints**: notify text must be confidentiality-safe (ntfy.sh is
  a public relay); the hook must never break the gate (never-crash-caller);
  silent no-op when `NTFY_TOPIC` unset; opt-in so the pre-commit hook stays silent.

## Findings by Specialist

### Security Specialist
- Zero blocking findings. Confidentiality is satisfied **by construction**: the
  three message strings interpolate only two integers (`passed`, `total`) into
  static templates — no paths, filenames, project names, secrets, branch names,
  usernames, or IDs cross the egress boundary to ntfy.sh.
- Opt-in default (`enabled=False`) correctly prevents the pre-commit hook from
  emitting notifications without explicit developer intent.
- Advisory: the broad `except Exception: pass` swallows even `ImportError`
  silently — not exploitable, but a developer debugging a misconfigured
  notification setup gets no signal. Suggested a 1-line stderr notice.
- Advisory (future): when the watcher vision is built, security-F1 (sentinel
  scoping) and security-F2 (absent-verdict-is-blocking) must be hard requirements
  behind a dedicated security review; the vision doc states them faithfully.
- Prime Objective: clear — no attribution/consent/value-flow surface.
- Confidence: 0.95

### QA Specialist
- ~95% branch coverage of `_notify_outcome`; the never-crash contract is verified
  directly with a side-effect-raising mock.
- **Blocking (Rule 15)**: `test_pass_fires_success` uses
  `kwargs.get("priority") != "high"`, which passes vacuously (the success call
  passes no `priority` kwarg, so `.get()` returns `None`).
- Advisory: the `ImportError` path (notify.py absent from `sys.path`) is
  swallowed but untested — and it is the load-bearing never-crash path.
- Advisory: `total == 0` (all checks skipped) reaches the `passed == total`
  branch and sends "All 0 checks passed"; document or test this edge.
- Verified non-findings: `except Exception:` is not a bare except (does not
  violate the coding standard); `args.notify` is always defined; the
  `@patch("notify.send_notification")` target is mechanically correct; the Rule 14
  mirror-structure exemption applies (scripts/ file, no `src/` counterpart).
- Confidence: 0.88

## Required Changes Before Merge

1. **QA-F1 (Rule 15, test quality)** — In `tests/test_quality_gate.py`
   `test_pass_fires_success`, replace `assert kwargs.get("priority") != "high"`
   with `assert "priority" not in kwargs`. The current assertion passes
   regardless of whether a priority kwarg is sent and would not catch a
   regression that adds `priority=` to the success path.

## Recommended Improvements (Non-Blocking)

1. **SEC-F1 + QA-F2 (convergent)** — Replace the bare `except Exception: pass`
   with a 1-line stderr notice (e.g. `except Exception as exc: ...stderr...`)
   to restore debuggability of a misconfigured notify setup while preserving the
   never-crash contract, and add a test exercising the import-failure
   never-raise path.
2. **QA-F3** — Add a docstring note (or a test) documenting that `total == 0`
   (all checks skipped) is treated as a pass.
